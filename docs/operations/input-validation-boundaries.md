# 输入校验与异常处理边界

本次重构按以下约定精简代码，不改变权限模型、数据库结构或中间件配置。

## 校验一次，不是省略校验

- HTTP 请求的必填、字符长度、枚举格式、数值范围由 Controller 的 `@Valid` 和 DTO 约束负责。注册和改密另在同一 HTTP 入口检查 BCrypt 的 72 个 UTF-8 字节限制；它不同于 72 个 Java 字符。
- Service 接收已经验证的请求或由服务端构造的内部命令，不再为相同字段重复检查空对象、必填和长度。直接调用 Service 的新适配器应在自己的输入边界保证这些约定，不能把未验证的外部输入直接透传。
- 登录、旧密码验证中的字节上限属于凭据验证：保留原来的失败响应，不让超长凭据进入 BCrypt。刷新 Cookie 可能缺失，在刷新入口检查一次；私有查会话方法接收已计算的摘要，不重复判空和哈希。
- 数据库查询未命中、RBAC、跨组织归属、业务时间关系、补签原因，以及加锁后状态变化不是重复参数检查，仍由 Service 负责。
- 可选请求体和可选字段的默认值不是防御性兜底，不因本次重构删除。

## 只处理能明确分类的异常

- 活动缓存、Redis 限流和动态签到凭证存储，只把 Spring `DataAccessException` 转换为缓存降级或存储不可用；程序接线错误等其他运行时异常不伪装成 Redis 故障。
- JWT subject 解析只把 `NumberFormatException` 转成非法令牌；不捕获所有运行时异常。
- 缓存 JSON/版本校验、外部游标解析、数据库唯一冲突、后台任务隔离、Outbox 重试和 Kafka 消费日志脱敏具有具体失败语义，不能机械删除其捕获。
- Java 要求处理的受检异常继续按调用边界转换，不为减少 `try/catch` 数量而吞掉错误。

## 本次范围与后续约束

本次覆盖认证、岗位时间校验复用、报名及签到内部命令、活动缓存、JWT 解析、Redis 限流和动态签到凭证存储。参数负向测试迁到 HTTP 层；业务状态、事务与并发测试仍保留在 Service 层。此约定不是“仓库内所有判空均已移除”的承诺。

没有新增面向假设性损坏数据、极端溢出或罕见环境的运行时防御。以后若确实需要增加，先说明可发生的场景、代价和影响，再征求项目所有者同意。
